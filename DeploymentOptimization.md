# Vercel Deployment Optimization Guide

## Overview
This document outlines the necessary optimizations for deploying ClearMyDay to Vercel, considering it's a small-scale application (max 200 users) focused on calendar subscription functionality.

## 🚨 Critical Issues (Must Fix)

### 1. In-Memory Storage Replacement
**Current Problem**: Using `Map()` for storage doesn't work with Vercel's serverless functions.

**Files Affected**:
- `/src/lib/calendar-storage.ts` - Calendar configurations storage
- `/src/app/api/calendar/[token]/route.ts` - Rate limiting storage

**Solutions for Small Scale (200 users)**:

#### Option A: Vercel KV (Redis) - RECOMMENDED
- **Cost**: Free tier: 30,000 commands/month (sufficient for 200 users)
- **Setup**: Vercel dashboard → Storage → Create KV Database
- **Code Changes**: Replace `Map()` with KV operations
- **Pros**: Persistent, fast, built for Vercel
- **Cons**: Requires Vercel account setup

#### Option B: Simple File-Based Storage (Alternative)
- **Cost**: Free (uses Vercel's filesystem)
- **Setup**: No external services needed
- **Code Changes**: Store configs in `/tmp` directory
- **Pros**: No external dependencies
- **Cons**: Less reliable, not recommended for production

**Recommendation**: Use Vercel KV for reliability and simplicity.

### 2. Dynamic Base URL Generation
**Current Problem**: Hardcoded domain in subscription URLs.

**File**: `/src/app/api/generate-calendar/route.ts` (lines 43-45)

**Current Code**:
```typescript
const baseUrl = process.env.NODE_ENV === 'production' 
  ? 'https://your-domain.com'  // ❌ Hardcoded
  : `http://localhost:${process.env.PORT || 3000}`;
```

**Fixed Code**:
```typescript
const baseUrl = process.env.NODE_ENV === 'production'
  ? `https://${request.headers.get('host')}`  // ✅ Dynamic
  : `http://localhost:${process.env.PORT || 3000}`;
```

**Setup Required**: None - automatic with Vercel.

## ⚠️ Recommended Optimizations

### 3. Remove Unnecessary CORS Headers
**Current Problem**: CORS headers not needed for same-origin requests on Vercel.

**File**: `/src/app/api/calendar/[token]/route.ts` (lines 95-97)

**Action**: Remove CORS headers in production:
```typescript
// Remove these in production:
'Access-Control-Allow-Origin': '*',
'Access-Control-Allow-Methods': 'GET, OPTIONS',
'Access-Control-Allow-Headers': 'Content-Type'
```

### 4. Optimize Cache Headers
**Current**: 5-minute cache
**Recommended**: 1-hour cache (calendar data changes infrequently)

```typescript
'Cache-Control': 'public, max-age=3600', // 1 hour instead of 5 minutes
```

### 5. Rate Limiting Strategy
**For Small Scale (200 users)**:

#### Option A: Remove Rate Limiting (RECOMMENDED)
- **Reasoning**: 200 users won't cause abuse issues
- **Action**: Remove rate limiting code entirely
- **Pros**: Simpler code, no storage needed
- **Cons**: No protection against abuse

#### Option B: Simple Rate Limiting with Vercel KV
- **Use Case**: If you're concerned about abuse
- **Implementation**: Store rate limits in same KV database

**Recommendation**: Remove rate limiting for initial deployment, add later if needed.
